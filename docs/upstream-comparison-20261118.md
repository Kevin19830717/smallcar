# 与 r550-field-kit 最新版的对比

比较时间：2026-11-18。只下载、阅读和离线测试，没有部署到实车。

上游基线：`9d67bd1c49458c8763fb44ccd525fbdf85586973`。
最新主线：`15cb718`。相比基线有 3 次提交、101 个文件变化、增加 10790 行、删除 427 行。
三次提交为 SERVO_CAR_2、ESP32-C5 CSI、双车 FAS/场地建图/导航改进。

## 能不能拉取

可以克隆并已下载到独立目录。单纯下载不会改变小车程序。
不建议在当前 1003 运行目录直接 pull 或复制覆盖。这不是三项独立插件：导航、网页、采集、速度链与任务状态机一起变化，局部拼接可能无法启动或改变停车保护。
当前 1003 本地补丁并非上游完整提交链，不能把从旧版升级主线当成无冲突的快进。

## 重叠功能与影响

| 范围 | 当前1003快照 | 上游15cb718 | 升级重点 |
|---|---|---|---|
| 到点与朝向 | 普通巡航点仅位置；恢复朝向的工作稿尚未部署 | 普通停靠4cm/4°，RSSI站12cm/3°；小角度起转、轮速提前制动、停稳复核 | 上游方向值得参考，但会改变既有到达标准，不等于已解决这台车的摆头 |
| 行驶与恢复 | 原有分段导航、转向/后退恢复及失败计时修复 | 固定朝向路段、受控倒车、短退、定位一致性和打滑监督、受阻保留目标 | 需整套验证，不能只拷控制器参数 |
| motion_gate.py | 网页启动请求nonce、10秒有效期、STOP作废、互斥防排队 | 独立ROS速度门控节点，订阅guard_cmd_vel、许可和传感器 | 同名不同接口；上游文件不能替换当前文件后继续使用当前server.py |
| 速度输出 | Nav2和平滑器直接输出cmd_vel | 控制器→平滑→碰撞监视→最终门控→底盘 | 必须统一迁移launch、参数、后端和依赖，避免断链或旁路保护 |
| 尺寸与通道 | 实测约33×21cm；足迹±0.165/±0.105 | 默认足迹约28×22cm；局部/全局膨胀0.36/0.42m | 不能照搬较短车长；膨胀更大会改变狭窄通道通行与规划 |
| 速度 | 配置包含0.20m/s的导航上限 | 默认普通导航0.12m/s，加速0.20m/s² | 更保守，不能期望升级后一定更快 |
| 回充 | 最多5次、统一手动/自动红外接管、退出检查、累计时间/轮程限制 | 不同回充状态机；失败重试条件中仍有dock_retry_count<1，另有充电续作 | 直接覆盖会丢失当前五次策略，需逐项保留或明确替代 |
| 请求与网页 | 两页控制/诊断、明显失败提示、请求防重复 | 新场地页、车队页、Windows本地代理与任务检查点 | 当前面板/API不可与新后端混用；本地代理也不等于新电脑可无Python环境运行 |
| 记录 | 精简话题、诊断打包、总预算2GB轮换 | 提供手动导航录制和采集存储，未见当前FlightRecorder/retention机制 | 当前录包限额、失败证据和下载功能需要迁移保留 |
| 采集 | WS63接收/热力图；回传实验暂停 | SERVO旋转采集、C5 CSI、FAS双车双频以及站点存储 | 是不同硬件/协议流程，不能认作现有RSSI回传已经联调完成 |
| 深度避障 | 候选已回退、尚未启用 | 此次更新中未发现深度相机障碍输入；保护仍以scan为主 | 升级不能解决低于雷达平面的全部障碍 |
| 双车 | Windows按车型启动，同IP需要人工分清网络 | 端口转发、分车ROS域、运行区和许可、FAS走廊预约 | 仍需网络隔离及独立桩位；配置了双车运行区时不能照常勾自动回充 |

## 建议采用方式

1. 保留v1快照，另建测试分支/目录，以最新上游作为候选。
2. 先移植这台车的真实足迹、天线过滤、现场地图/桩位/点位，保持map_id一致。
3. 整套核对速度链、依赖和唯一串口/速度所有者；保留网页请求防重和2GB轮换。
4. 明确保留哪套回充次数、退出检查及充电确认，再迁移任务状态机。
5. 静态检查之后，分别验收到点定向、狭窄通道、障碍短退、断流停车、红外对接。通过后才切换正式启动入口。
