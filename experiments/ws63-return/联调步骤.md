# 两块 WS63 RSSI 回传联调

源码基于 R550 Field Kit 9d67bd1。工作副本独立放置，原部署 ZIP 可作为采集版回退来源。

## 本机模拟服务器

模拟程序使用 Python 标准库，人工生成 RSSI，HTTP 在本机代替 SLE 传输。网页标有模拟模式，可观察计数和曲线。命令在本目录执行。

```powershell
python simulate_return.py --db demo.sqlite --demo --port 8893
```

在 Windows 浏览器打开 http://127.0.0.1:8893/ 。服务器只监听本机。虚拟机中的 127.0.0.1 指向虚拟机自身。前台运行时按 Ctrl+C 退出。

可重复运行性能和故障测试，每轮指定一个新的数据库文件。

```powershell
python simulate_return.py --db trial01.sqlite --test-report trial01.json
```

测试覆盖 10 Hz 上报、500 条突发、重复去重、错误字段拒绝、写盘后丢确认、重连和数据库重开。JSON 中的性能数值只描述本机 HTTP 到 SQLite 提交和确认的耗时。实际基站串口程序仍为 collect_base.py。模拟数据库按会话和序号保存唯一条目，能保留乱序；实际车端发送队列按序逐条写入，串口采集器按递增序号去重。

完整 SDK 的链接、烧录包生成和扫描与连接共存仍待验证。请先完成对应 SDK 中的构建，再进行后面的实板验收。

## 连接和编译

1. 在原先用于烧录这两块板的 WS63 SDK 中备份旧的 `src/application/samples/bt/sle/beacon_survey`。将本目录的 `beacon_survey` 放入同一位置。首次接入时按 `sdk_integration` 的片段合并上级 CMake 和 Kconfig。已经接入旧版本时只替换示例目录。保留旧 TX、RX 烧录包。
2. 在 SDK 的 SLE Sample 中分别选择 `R550 fixed RSSI beacon with SLE return server` 和 `R550 mobile RSSI scanner with SLE return client`。车载版开启 AT_SUPPORT_PLT 和现有 115200 串口配置。两个角色各自构建。原 Linux SDK 命令为 `python build.py -c ws63-liteos-app -j8`。每次切换角色后使用独立的干净构建配置，将产物分别保存为基站版和车载版。
3. 对照板子与串口，只给基站板烧 TX 包，只给车载板烧 RX 包。基站板的 USB 串口接基站电脑，车载板仍接 RDK。第一次验证让车静止。

## 静止验收

在基站电脑确认实际 COM 号，关闭占用该串口的工具。安装依赖后运行以下命令，输出文件使用新文件名。

```powershell
python -m pip install pyserial
python collect_base.py --port COM5 --output base_trial01.csv
```

- 基站串口的 `+BCUPBASE:0` 表示回传服务和广播启动请求成功。车载 `+BCUPCLIENT:0,<session>` 表示客户端注册成功。启动日志可能早于打开串口。
- 最终以基站电脑连续出现 `BASE rx=... seq=... RSSI=... dBm` 为准，并在新生成的 CSV 中看到同样的行。在车端面板打开广播采集，用 `raw.csv` 的 `rx_sequence` 对照基站 CSV 的 `sequence`，同时对照 RSSI。请在同一次车载板开机和同一采集窗口内比对。车载板持续扫描，基站可能收录采集窗口外的样本。
- 车载板每秒打印 `+BCUP:state,scanning,queued,dropped,confirmed`。状态 8 是连接且属性已发现。扫描位为 1 只表示协议栈报告已开启扫描，还应观察实际样本是否持续出现。
- 在走车前先检查连续 30 秒的样本间隔和回传队列。再用安全的射频遮挡或关闭基站验证断连后能重新连接。关闭基站同时会失去采样信标，因此这一步只验证重连。若连接后样本停更，优先核查 SDK 是否支持扫描与连接共存，保留采集版作为回退。

每次 SSAP 写请求发送一条 18 字节的原始样本，包含随机会话号、接收序号、车载板接收时间和 RSSI。车端仍输出原有的 `+BCHELLO`、`+BCRSSI` 和 `+BCSTATUS`。回传队列为 128 条 RAM，断线时等待重连，满后累计丢弃数，掉电不补传。确认表示基站板处理过写请求，基站电脑落盘以 CSV 为准。第一版不在空口传地图坐标，坐标仍保存在 RDK 的采集文件。
